# Тестирование

Проверки на компьютере запускаются без стика и бризера. Они охватывают собственный C++ и Python-инструменты; аппаратные испытания выполняются отдельно по [плану](one-visit-test.md).

## Запуск

Нужны Bash, Python 3.9+ и компилятор C++17 с работающими ASan, UBSan и TSan. Скрипт пробует Clang, затем GCC; переменная `CXX` задаёт выбор явно.

```sh
scripts/test-host.sh
scripts/test-host.sh --coverage
```

Для покрытия GCC нужен соответствующий `gcov` версии 9 или новее. Для Clang нужны совместимые `llvm-profdata` и `llvm-cov`; на macOS они также ищутся через `xcrun`.

## Что проверяется

| Уровень | Сценарии | Граница модели |
| --- | --- | --- |
| Протокол | CRC, длины, шум, частичные и склеенные кадры, восстановление после паузы | Эталонные пакеты upstream и синтетические данные |
| Команды | Предчтение, ограничения, очередь, таймауты, отказ и подтверждение | Симулятор Tion |
| HomeKit | Сервисы/IID, значения, запись характеристик, ускорение, фильтр и переименование | Модель API HomeSpan |
| ESP32-интеграция | Реальный адаптер, UART-задача, оба скетча, watchdog и восстановление | Заглушки ESP-IDF/FreeRTOS, управляемый поток вместо планировщика ESP32 |
| Сопряжение | Повреждённые данные и ошибки операций NVS | NVS/SRP-модели; криптография HomeSpan не тестируется заново |
| Параллельность | Публикация состояния и исходов команд | Двухпоточный тест под TSan |
| Python | Сбор и оценка диагностики, проверка публичного снимка | Синтетические файлы и ответы |

Платформенные интеграционные сценарии проходят путь **HomeKit → ControlAccess → UART-задача → протокол → симулятор бризера → состояние HomeKit**. Отдельный набор использует упрощённый адаптер для точечных проверок поведения. Сценарии скетчей запускаются в отдельных процессах, чтобы не переносить глобальное состояние между тестами.

## Покрытие и отчёты

`--coverage` требует **100% строк и ветвей** для всех `.h`, `.cpp` и `.ino` в `libraries/Tion4SCore/src` и `firmware`. Включены настоящий ESP32-адаптер и обе прошивки. Файл, не участвующий ни в одном тесте, тоже считается пропуском. Тестовые заглушки, сторонние библиотеки и Python не входят в этот процент.

GCC и Clang по-разному считают строки и ветви; сравнивать нужно долю покрытия в одной системе измерения. Полное покрытие означает выполнение измеренных ветвей, а не доказательство отсутствия дефектов или всех возможных чередований задач.

Артефакты находятся в `.build/host/`; база `.build/host/compile_commands.json` используется `clang-tidy` и `clangd`. Тесты собираются со строгими предупреждениями как ошибками, ASan/UBSan и отдельным TSan-прогоном.

## Сборка и CI

После [установки инструментов](../README.md#установка) выполните:

```sh
scripts/check.sh
```

Скрипт запускает host-тесты и пять вариантов компиляции: HomeSpan/UART spike, переносимое ядро для ESP32, `TionReadOnly`, обычный `TionHomeKit` и его диагностический вариант. Он не прошивает устройства.

[GitHub Actions](https://github.com/viventu/tion-homekit/actions/workflows/check.yml) запускает GCC с порогом покрытия, Clang с санитайзерами и `clang-tidy`, проверку публичного дерева и все варианты прошивки. Для `main` обязательны статусы `host (g++)`, `host (clang++)` и `firmware`.

Успешная сборка не проверяет электрические уровни, реальный планировщик, поведение приложения «Дом» и длительную работу. Эти результаты записываются отдельно в [сводке проверок](validation.md).
