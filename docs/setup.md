# Установка и восстановление

Статус: ROM-чтение, резервные копии, запись/проверка сегментов и настройка выполнены на двух стиках с Flash 16 МБ и двух Tion Family 4S `02D0`; APP-обновление до GM1 с побайтной проверкой сохранности NVS выполнено на обоих. Сопряжения сохранились, базовое управление подтверждено, суточные прогоны продолжаются. Полная обратная запись заводского образа и кнопочный reset аппаратно NOT RUN. Электрические уровни и запас питания прибором не измерялись; подробные результаты — в [журнале](validation.md). Один стик обслуживает один бризер. Приведённые команды выполняются **только на снятом стике**. Стик не должен получать питание от Tion и Mac одновременно.

## Подготовка

1. Соберите проект закреплёнными версиями Arduino CLI 1.5.1, Arduino-ESP32 3.3.8 и HomeSpan 2.1.8 по [README](../README.md). Выполните `scripts/check.sh`. Обычный образ будет в `.build/homekit/`, диагностический — в `.build/homekit-diagnostics/`. Для установленного устройства выбирайте один из них осознанно: диагностический вариант открывает в доверенной локальной сети страницу `/tion-status` без HAP-аутентификации.
2. Установите `esptool` 5.2.0 из пакета Arduino-ESP32. На Mac узнайте USB-порт снятого стика (`ls /dev/cu.usbmodem*`). Войдите в ROM, удерживая BOOT при подключении к USB, затем отпустите. Проверенный на наших стиках режим подключения — `--before no-reset --after no-reset`.
3. Прочитайте MAC и параметры Flash, сравните с конкретным стиком и его резервной копией. Не используйте данные второго стика. Не меняйте eFuse, Secure Boot, Flash Encryption или прошивку контроллера Tion.

Пример переменных для команд ниже; подставьте **свой** порт и каталог установленного toolchain:

```sh
ESPTOOL=/path/to/esptool
PORT=/dev/cu.usbmodemXXXX
BUILD=.build/homekit
BOOT_APP0=/path/to/arduino-esp32/tools/partitions/boot_app0.bin
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset read-mac
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset flash-id
```

Адреса ниже применимы только после проверки таблицы разделов исходного стика: NVS `0x9000` размером `0x5000` и APP `0x10000` размером `0x300000`. Если исходная разметка другая, Flash зашифрована или ревизия неизвестна, остановитесь до отдельного плана переноса; простая запись новой partition table не сохраняет данные автоматически.

До первой записи сохраните полный образ **каждого** стика по отдельности, проверьте размер 16 777 216 байт и SHA-256. Каталог `.private/` исключён из Git; резервные копии содержат NVS с настройками и не подходят для публикации.

```sh
mkdir -p .private/backups
umask 077
BACKUP=.private/backups/this-stick-original.bin
# Choose a new filename; never overwrite an earlier backup.
test ! -e "$BACKUP" && \
  "$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset read-flash --no-progress 0 0x1000000 "$BACKUP" && \
  test "$(wc -c < "$BACKUP")" -eq 16777216 && \
  shasum -a 256 "$BACKUP"
```

Сохраните MAC, хэш и соответствие имени файла конкретному стику вне репозитория. Проверяйте свободное место до чтения. На наших стиках чтение 16 МБ при 115200 бод заняло около 24 минут на каждый.

## Первая запись

Проверьте, что собранный образ предназначен для ESP32-S3, Flash 16 МБ, DIO и раздела приложения 3 МБ. Таблица разделов должна соответствовать `huge_app.csv` закреплённого Arduino core. Сначала завершите резервное копирование и проверьте повторный вход в ROM. Затем запишите только четыре указанных сегмента; NVS по `0x9000–0xdfff` не стирайте и не переносите между стиками.

```sh
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset write-flash --flash-mode dio --flash-freq 80m --flash-size 16MB \
  0x0 "$BUILD/TionHomeKit.ino.bootloader.bin" \
  0x8000 "$BUILD/TionHomeKit.ino.partitions.bin" \
  0xe000 "$BOOT_APP0" \
  0x10000 "$BUILD/TionHomeKit.ino.bin"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset verify-flash \
  0x0 "$BUILD/TionHomeKit.ino.bootloader.bin" \
  0x8000 "$BUILD/TionHomeKit.ino.partitions.bin" \
  0xe000 "$BOOT_APP0" \
  0x10000 "$BUILD/TionHomeKit.ino.bin"
```

После проверки полностью отключите USB и подключите стик заново **без BOOT**. На тестовых стиках программный reset после записи не всегда запускал Setup AP; физический цикл питания запускал. Дождитесь сети `Tion-Setup-XXXXXX`, где суффикс образован последними байтами MAC. Подключитесь к ней с заводским паролем AP `homespan`; это общий пароль HomeSpan, а не код сопряжения. В открывшейся captive-форме HomeSpan выберите домашний Wi-Fi и нажмите `SUBMIT`, затем обязательно задайте свой отдельный восьмизначный код и нажмите `SAVE`. Пустое поле оставит неизвестный пользователю случайный bootstrap-код, поэтому первое сопряжение с ним невозможно. AP работает пять минут. Пароль и код нигде в проекте не записывайте. В приложении «Дом» добавьте аксессуар через «Другие варианты», задайте различимые имена двум устройствам и выберите комнату.

До установки в Tion проверьте, что аксессуар сопряжён. Затем отключите стик от Mac и вставьте в штатный интеграционный порт **соответствующего** бризера без BOOT. При нормальном запуске плитка перестанет показывать «Не отвечает», состояние вентилятора совпадёт с Tion, а диагностическая сборка покажет `DEV_INFO`, свежие UART-состояния и heartbeat. В GM1 управление доступно автоматически при поддерживаемой версии контроллера и свежем состоянии. Переключателя допуска нет; после неудачной команды можно отправить новую явную команду. Свежий pre-read, одна запись и проверка результата обязательны. На `02D0` команды проверены на наших двух бризерах; другие версии в этом проекте аппаратно не подтверждены.

## Обновление приложения без потери сопряжения

Перед обновлением снимите нужный стик с бризера, подключите с BOOT, повторно подтвердите его MAC и наличие проверенной полной резервной копии. Сохраните **текущую** NVS в приватный файл `0600`, запишите только APP по `0x10000`, отдельно проверьте APP и сравните NVS до/после побайтно. Имена файлов в примере относятся только к одному стику; не перезаписывайте уже сохранённую копию. При изменившемся bootloader/partition layout обновление только APP неприменимо без отдельного плана.

```sh
set -e
umask 077
BACKUP_DIR=.private/backups/this-stick-update-YYYYMMDD-HHMMSS
mkdir -m 700 "$BACKUP_DIR" || exit 1
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset read-flash --no-progress 0x9000 0x5000 "$BACKUP_DIR/before.nvs"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset write-flash --flash-mode dio --flash-freq 80m --flash-size 16MB 0x10000 "$BUILD/TionHomeKit.ino.bin"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset verify-flash 0x10000 "$BUILD/TionHomeKit.ino.bin"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset read-flash --no-progress 0x9000 0x5000 "$BACKUP_DIR/after.nvs"
cmp "$BACKUP_DIR/before.nvs" "$BACKUP_DIR/after.nvs"
```

При несовпадении NVS не устанавливайте стик в Tion до разбора причины. Если APP не запускается, снова войдите в ROM с BOOT и верните ранее проверенный APP именно этого стика; полное восстановление заводского образа заменит NVS сохранённой версией и может сбросить более поздние Wi-Fi/HomeKit-настройки. После успешного обновления выполните физический цикл питания без BOOT и проверьте версию, UART и отвечающую плитку «Дом».

## Возврат заводского образа и повторная настройка

Если APP не запускается, снятый стик должен снова определяться в ROM с BOOT. Сначала повторно сверяют MAC с приватным манифестом и полный SHA-256 резервной копии. Для восстановления прежнего рабочего приложения предпочтительно вернуть его APP и сохранить текущую NVS. Полная запись исходного Flash-образа заменяет все настройки, в том числе NVS; её выбирают только для явного возврата этого же стика к состоянию его резервной копии. Такой полный restore в проекте пока NOT RUN. После отдельного preflight команда для проверенной 16-МБ копии выглядит так:

```sh
set -e
BACKUP=.private/backups/this-stick-original.bin
# First check this file's SHA-256 against this stick's private manifest.
test "$(wc -c < "$BACKUP")" -eq 16777216
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset write-flash --flash-mode keep --flash-freq keep --flash-size keep 0 "$BACKUP"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset verify-flash 0 "$BACKUP"
```

Для смены Wi-Fi или утраченного setup-кода HomeSpan документирует Command Mode: на **уже работающем снятом стике** удержать BOOT/GPIO0 три секунды и отпустить при быстром мигании. Два коротких нажатия выбирают действие 3 (Setup AP), затем удержание три секунды подтверждает выбор. Это отличается от удержания BOOT при подключении питания, которое запускает ROM. Последовательность на нашей плате аппаратно NOT RUN; если мигание не соответствует ожидаемому, действие не подтверждают. Долгое удержание десять секунд выполняет factory reset HomeSpan и удаляет Wi-Fi/сопряжения, поэтому его не используют как обычный перезапуск. Источник: [HomeSpan 2.1.8 UserGuide](https://github.com/HomeSpan/HomeSpan/blob/107ffc07f4455754ea89068d8cf2e992de3583e6/docs/UserGuide.md).

## Известные ограничения интерфейса

- «Ускорение на 5 минут» — локальный перевод обычной скорости на 6/6 с условным возвратом, а не native Turbo Tion Remote. Если во время таймера пропадёт связь, произойдёт перезапуск или любая команда завершится ошибкой, автоматическая обратная запись не выполняется; скорость может остаться 6/6. В этом случае выставьте нужную скорость штатным управлением или в «Доме» после восстановления связи.
- «Сброс фильтра после замены» не испытан с действительно заменённым фильтром. Команда допускается только при выключенном вентиляторе и запрещённом нагреве.
- Начиная с `rc3-dev` температуры публикуются в диапазоне −50…100 °C; отображение отрицательных значений в «Доме» ещё NOT RUN. Сырое значение всегда видно в диагностике.
- При первом сопряжении Apple «Дом» может показать типовые имена для звука, рециркуляции и подсветки. На втором устройстве их сопоставили с UART и переименовали в настройках «Дома»; причина исходных имён не установлена.
