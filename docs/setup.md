# Установка и восстановление

Инструкция предназначена для ESP32-S3 с Flash 16 МБ и разметкой `huge_app`. Сначала сверьте [совместимость и подключение](hardware.md). Прошивка выполняется **только на снятом с бризера стике**, с одним источником питания.

ROM-чтение, запись сегментов, настройка и обновление с сохранением сопряжения проверены на целевой конфигурации. Полное восстановление Flash из резервной копии и кнопочный сброс HomeSpan ещё не испытаны; электрические уровни и запас питания прибором не измерены. Подробности — в [сводке проверок](validation.md).

## Подготовка

1. Соберите проект закреплёнными версиями Arduino CLI 1.5.1, Arduino-ESP32 3.3.8 и HomeSpan 2.1.8 по [README](../README.md). Выполните `scripts/check.sh`. Обычный образ будет в `.build/homekit/`, диагностический — в `.build/homekit-diagnostics/`. Для установленного устройства выбирайте один из них осознанно: диагностический вариант открывает в доверенной локальной сети страницу `/tion-status` без HAP-аутентификации.
2. Найдите `esptool` 5.2.0 в установленном пакете Arduino-ESP32. Определите порт снятого стика: на macOS это обычно `/dev/cu.usbmodem*`, на Linux — `/dev/ttyACM*`. Войдите в ROM, удерживая BOOT при подключении к USB, затем отпустите. Команды ниже используют проверенный режим `--before no-reset --after no-reset`.
3. Прочитайте MAC и параметры Flash, сопоставьте их с конкретным стиком и его резервной копией. Не переносите настройки между устройствами. Не меняйте eFuse, Secure Boot, Flash Encryption или прошивку контроллера Tion.

Пример переменных для команд ниже; подставьте **свой** порт и каталог установленного toolchain:

```sh
ESPTOOL=/path/to/esptool
PORT=/dev/cu.usbmodemXXXX
BUILD=.build/homekit
BOOT_APP0=/path/to/arduino-esp32/tools/partitions/boot_app0.bin
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset read-mac
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset flash-id
```

Адреса ниже применимы только после проверки таблицы разделов исходного стика: NVS `0x9000` размером `0x5000` и APP `0x10000` размером `0x300000`. Если исходная разметка другая, Flash зашифрована или ревизия неизвестна, остановитесь до отдельного плана переноса; простая запись новой partition table не сохраняет данные автоматически.

## Резервная копия

До первой записи сохраните полный образ **каждого** стика по отдельности, проверьте размер 16 777 216 байт и SHA-256. Каталог `.private/` исключён из Git; резервные копии содержат NVS с настройками и не подходят для публикации.

```sh
mkdir -p .private/backups
umask 077
BACKUP=.private/backups/this-stick-original.bin
# Choose a new filename; never overwrite an earlier backup.
test ! -e "$BACKUP" && \
  "$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset read-flash --no-progress 0 0x1000000 "$BACKUP" && \
  test "$(wc -c < "$BACKUP")" -eq 16777216 && \
  shasum -a 256 "$BACKUP"
```

Сохраните MAC, хэш и соответствие имени файла конкретному стику вне репозитория. Проверяйте свободное место до чтения. Чтение 16 МБ при 115200 бод может занять около 25 минут.

## Первая запись

Проверьте, что собранный образ предназначен для ESP32-S3, Flash 16 МБ, DIO и раздела приложения 3 МБ. Таблица разделов должна соответствовать `huge_app.csv` закреплённого Arduino core. Сначала завершите резервное копирование и проверьте повторный вход в ROM. Затем запишите только четыре указанных сегмента; NVS по `0x9000–0xdfff` не стирайте и не переносите между стиками.

```sh
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset write-flash --flash-mode dio --flash-freq 80m --flash-size 16MB \
  0x0 "$BUILD/TionHomeKit.ino.bootloader.bin" \
  0x8000 "$BUILD/TionHomeKit.ino.partitions.bin" \
  0xe000 "$BOOT_APP0" \
  0x10000 "$BUILD/TionHomeKit.ino.bin"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset verify-flash \
  0x0 "$BUILD/TionHomeKit.ino.bootloader.bin" \
  0x8000 "$BUILD/TionHomeKit.ino.partitions.bin" \
  0xe000 "$BOOT_APP0" \
  0x10000 "$BUILD/TionHomeKit.ino.bin"
```

## Wi-Fi и сопряжение

После проверки полностью отключите USB и подключите стик заново **без BOOT**. При отсутствии сохранённых Wi-Fi-настроек появится сеть `Tion-Setup-XXXXXX`; суффикс зависит от стика.

1. Подключитесь к ней с паролем AP `homespan`. Это общий пароль сети настройки, а не код HomeKit.
2. В форме HomeSpan выберите домашний Wi-Fi и нажмите `SUBMIT`.
3. Задайте собственный восьмизначный код сопряжения и нажмите `SAVE`. Пустое поле оставляет неизвестный случайный bootstrap-код, с которым ручное сопряжение невозможно.
4. В приложении «Дом» выберите «Добавить аксессуар» → «Другие варианты», введите свой код и назначьте комнату.

AP работает пять минут. Выполняйте настройку в доверенной обстановке. Для каждого стика используйте отдельный код; не записывайте коды и Wi-Fi-пароли в проект.

## Подключение к бризеру

После сопряжения отключите стик от компьютера и установите без BOOT в проверенный интеграционный порт бризера. Дождитесь подключения к Wi-Fi и свежего состояния UART. В «Доме» должны появиться актуальные питание и скорость; для подробной проверки доступна [диагностика](diagnostics.md).

Управление доступно автоматически при поддерживаемом контроллере и свежем состоянии. Переключателя допуска нет. Если команда завершилась ошибкой, сначала проверьте её причину; новая явная команда возможна после восстановления связи и условий записи.

## Обновление приложения без потери сопряжения

Перед обновлением снимите нужный стик с бризера, подключите с BOOT, повторно подтвердите его MAC и наличие проверенной полной резервной копии. Сохраните текущий APP для отката и **текущую** NVS в приватные файлы, запишите только APP по `0x10000`, отдельно проверьте APP и сравните NVS до/после побайтно. Замените `YYYYMMDD-HHMMSS` в имени каталога датой и временем обновления; не перезаписывайте уже сохранённую копию. При изменившемся загрузчике или разметке обновление только APP неприменимо без отдельного плана.

```sh
set -e
umask 077
BACKUP_DIR=.private/backups/this-stick-update-YYYYMMDD-HHMMSS
mkdir -m 700 "$BACKUP_DIR" || exit 1
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset read-flash --no-progress 0x10000 0x300000 "$BACKUP_DIR/before.app.bin"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset verify-flash 0x10000 "$BACKUP_DIR/before.app.bin"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset read-flash --no-progress 0x9000 0x5000 "$BACKUP_DIR/before.nvs"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset write-flash --flash-mode dio --flash-freq 80m --flash-size 16MB 0x10000 "$BUILD/TionHomeKit.ino.bin"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset verify-flash 0x10000 "$BUILD/TionHomeKit.ino.bin"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset read-flash --no-progress 0x9000 0x5000 "$BACKUP_DIR/after.nvs"
cmp "$BACKUP_DIR/before.nvs" "$BACKUP_DIR/after.nvs"
```

При несовпадении NVS не устанавливайте стик в Tion до разбора причины. Если новый APP не запускается, снова войдите в ROM с BOOT и верните сохранённый `before.app.bin` этого стика по адресу `0x10000`, затем выполните `verify-flash`. Это откат только приложения при прежней разметке; полное восстановление заводского образа также заменит NVS и может сбросить более поздние настройки. После успешного обновления выполните физический цикл питания без BOOT и проверьте версию, UART и отвечающую плитку «Дом».

## Возврат заводского образа

Если APP не запускается, введите снятый стик в ROM с BOOT. Сначала сверьте MAC с записью о резервной копии и её полный SHA-256. Для восстановления прежнего рабочего приложения предпочтительно вернуть его APP и сохранить текущую NVS. Полная запись исходного Flash-образа заменяет все настройки, в том числе NVS; её выбирают только для явного возврата этого же стика к состоянию его резервной копии. Полное восстановление Flash ещё не испытано на целевой плате (**NOT RUN**). Команды ниже описывают этот путь для проверенной 16-МБ копии; перед выполнением нужны проверка оборудования, разметки и принадлежности копии этому стику:

```sh
set -e
BACKUP=.private/backups/this-stick-original.bin
# First check this file's SHA-256 against this stick's private manifest.
test "$(wc -c < "$BACKUP")" -eq 16777216
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset write-flash --flash-mode keep --flash-freq keep --flash-size keep 0 "$BACKUP"
"$ESPTOOL" --chip esp32s3 --port "$PORT" --baud 115200 --before no-reset --after no-reset verify-flash 0 "$BACKUP"
```

## Повторная настройка кнопкой

Для смены Wi-Fi или утраченного кода HomeSpan документирует Command Mode: на **уже работающем снятом стике** удержать BOOT/GPIO0 три секунды и отпустить при быстром мигании. Два коротких нажатия выбирают действие 3 (Setup AP), затем удержание три секунды подтверждает выбор. Это отличается от удержания BOOT при подключении питания, которое запускает ROM. Последовательность на целевой плате аппаратно **NOT RUN**; если мигание не соответствует ожидаемому, действие не подтверждают. Долгое удержание десять секунд выполняет factory reset HomeSpan и удаляет Wi-Fi/сопряжения, поэтому его не используют как обычный перезапуск. Источник: [HomeSpan 2.1.8 UserGuide](https://github.com/HomeSpan/HomeSpan/blob/107ffc07f4455754ea89068d8cf2e992de3583e6/docs/UserGuide.md).

## Известные ограничения интерфейса

- «Ускорение на 5 минут» — локальный перевод обычной скорости на 6/6 с условным возвратом, а не native Turbo Tion Remote. Если во время таймера пропадёт свежее состояние бризера, произойдёт перезапуск или любая команда завершится ошибкой, автоматическая обратная запись не выполняется; скорость может остаться 6/6. В этом случае выставьте нужную скорость штатным управлением или в «Доме» после восстановления связи.
- «Сброс фильтра после замены» не испытан с действительно заменённым фильтром. Команда допускается только при выключенном вентиляторе и запрещённом нагреве.
- Температуры публикуются в диапазоне −50…100 °C; отображение отрицательных значений в «Доме» ещё не проверено. Исходное значение доступно в диагностике.
- При первом сопряжении Apple «Дом» может показать типовые имена для звука, рециркуляции и подсветки. Их можно переименовать в настройках аксессуара после определения назначения. Причина исходных имён не установлена.
