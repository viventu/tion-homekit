# Проверка бинарных артефактов

Инструкция для сопровождающего перед распространением `.bin` или `.elf`. Исходники проекта доступны по [0BSD](../LICENSE), а компоненты связанной ESP32-прошивки имеют собственные условия. Пока проверка конкретного бинарника не завершена, выпуск содержит только исходники и инструкцию локальной сборки.

## Состав сборки

[Реестр зависимостей](../third_party/README.md) фиксирует прямые версии и уведомления HomeSpan/протокольных данных. Он не является полным SBOM итогового ELF: в образ также входят компоненты Arduino-ESP32, ESP-IDF, криптография, runtime компилятора и предсобранные библиотеки SoC.

Для каждого кандидата используйте его ELF и linker map. Секция `Archive member included` помогает найти архивы и объектные файлы, но сама не сообщает лицензии; linker GC также может удалить часть секций. Предварительная инвентаризация другой версии не считается готовым списком для нового выпуска.

## Порядок проверки

1. Сохраните испытанные APP, bootloader и таблицу разделов, их размеры и SHA-256. Зафиксируйте публичный commit/tree, FQBN и версии инструментов.
2. Сопоставьте каждый связанный компонент с пакетом, точной версией, исходниками, лицензией и требуемым notice. Проверяйте вложенные зависимости, а не только LICENSE верхнего уровня.
3. Подготовьте полный SBOM, комплект notices и необходимые исходники/материалы согласно условиям соответствующих компонентов. Не выдавайте список прямых зависимостей за SBOM бинарника.
4. Сверьте assets с [заметками о выпуске](release-notes-template.md): назначение, адреса записи, размер, хэш, совместимость и восстановление. Различайте обычную и диагностическую сборки.
5. Проверьте готовый draft release. Если состав или условия распространения не подтверждены, оставьте выпуск только с исходниками.

Не включайте NVS, полный Flash, `.merged.bin`, частные конфиги и журналы эксплуатации. Обновление прошивки не должно переносить credentials одного устройства на другое.

## Источники

Проверка выполняется по версиям конкретной сборки: [Arduino-ESP32 3.3.8](https://github.com/espressif/arduino-esp32/tree/3.3.8) и его [LICENSE.md](https://github.com/espressif/arduino-esp32/blob/3.3.8/LICENSE.md), [ESP-IDF v5.5.4](https://github.com/espressif/esp-idf/tree/v5.5.4), [реестр лицензий ESP-IDF 5.5](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32/COPYRIGHT.html), [HomeSpan 2.1.8](https://github.com/HomeSpan/HomeSpan/tree/107ffc07f4455754ea89068d8cf2e992de3583e6).

Текущая Arduino CLI сборка не создаёт ESP-IDF `project_description.json`. Поэтому применение инструментов SBOM, которым нужен этот файл, требует отдельной адаптации и проверки полноты результата.
