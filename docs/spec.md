# Контракт устройства — Draft

Один стик обслуживает один Tion 4S. Два стика используют общий код, но разные NVS, Wi-Fi-настройки, HomeKit identity и коды сопряжения. На обоих стиках установлен `0.2.0-gm1-diag`: подтверждены свежий UART, сохранение сопряжения, удаление переключателя допуска и питание/скорость через HomeKit. Идут отдельные суточные прогоны; см. [журнал GM1](gm1-validation.md). Первый бризер прошёл основной набор команд ещё на `rc1`, второй — питание, рециркуляцию, звук, подсветку и полный пятиминутный boost на `rc2`. Контракт сохраняет статус Draft до проверки защитных сценариев и длительной работы нового кандидата.

## Возможности и кандидаты для HomeKit

Владелец запросил полный набор: питание, все скорости, состояние, нагрев, уставку, температуры, рециркуляцию, ускорение, фильтр, звук и подсветку. Пределы проверки на двух `02D0` перечислены выше; контракт до релиза остаётся Draft. Apple «Дом» сам раскладывает несколько сервисов и датчики по отдельным плиткам; один экран с произвольными элементами стандартный HAP не предоставляет. Сброс фильтра — действие после замены фильтра, не автоматическая реакция на предупреждение. Отрицательные температуры нельзя заменять нулём ради HAP-диапазона.

## Инварианты

| ID | Правило |
| --- | --- |
| S-01 | До первого валидного ответа нет авторитетного состояния и нет команд изменения режима. |
| S-02 | Reported state, pending intent, возраст/свежесть и состояние связи раздельны. Успех callback HomeSpan означает лишь принятие в ограниченную очередь, не аппаратное выполнение. |
| S-03 | Команда меняет только запрошенные поля на основе свежего полного состояния. При устаревшей базе или гонке с пультом сначала повторное чтение либо отказ; слепой full-state write запрещён. |
| S-04 | Служебный обмен имеет приоритет над HAP/Wi-Fi/provisioning; измеряется максимальная реальная пауза, отдельно планирование и байты в UART. |
| S-05 | Потеря Wi-Fi/HomeKit сама не меняет режим Tion. После reconnect просроченные намерения отбрасываются; состояние бризера главнее. |
| S-06 | Изменение setpoint не включает нагрев или бризер. Разрешение нагрева и фактическая работа ТЭНа различаются. |
| S-07 | Выключение и скорость 0 обрабатываются явно; повторное включение использует известную допустимую скорость. Преобразование стабильно для каждой подтверждённой ступени и фактического max. |
| S-08 | Не показывать охлаждение, неподтверждённый Auto, CO₂/PM2.5, ложную комнатную температуру или рециркуляцию как direction/swing. |
| S-09 | HomeKit identity и IID сервисов/характеристик постоянны при обычных обновлениях; смена схемы — контролируемая миграция. |
| S-10 | Автоматических сбросов фильтра/настроек нет. Наш код пишет NVS только при начальной смене кода сопряжения. HomeSpan 2.1.8 отдельно пишет счётчик reboot и флаг OTA при запуске; их поведение фиксируется как ограничение сторонней библиотеки. OTA не включена. |

## Установленный образ и новый кандидат

Исторический `0.1.1-diag` отражал только свежее состояние через Fan и отвергал записи. Начиная с `0.2.0-rc1-diag` первые характеристики Fan сохранены в прежнем порядке, чтобы не менять их IID. `CurrentFanState` выводится из питания и ступени, не из датчика потока; при устаревшем состоянии `StatusFault=1`.

В `0.2.0-gm1` сопряжённый HomeKit управляет поддерживаемым бризером сразу после получения свежего состояния. Переключатель «Разрешить управление» и срок 30 минут удалены по решению владельца 2026-09-26. На прежних `rc1`/`rc2` этот временный допуск сохраняется до обновления. Идентификаторы удалённого сервиса 13–15 не переиспользуются: оставшиеся плитки сохраняют свои IID. Владелец подтвердил на обоих устройствах исчезновение переключателя допуска и работу питания/скорости без повторного сопряжения; независимая полная HAP validation остаётся NOT RUN.

Вызов HomeSpan означает только принятие в ограниченную очередь. Совпадение с целью подтверждает свежий pre-read UART (исход `Unchanged`). У UART-адаптера один владелец: он читает свежую базу, один раз пишет полный state и отдельно проверяет изменённое поле. Для `02D0` ответ сверяется по порядку и полям, поскольку наблюдавшиеся request ID не совпадают с контрактом upstream. На таймауте запись не повторяется. Heartbeat остаётся приоритетным. Ошибка завершает текущую команду, удаляет ожидающую команду и отменяет автоматический возврат действующего ускорения; новая явная команда допускается при исправной связи без ручного rearm.


Переименование сервиса контроллером записывает только его `ConfiguredName`: `rc3-dev` сохраняет новое имя и больше ничего не делает. Раньше такая запись вызывала `update()` с прежним значением переключателя, поэтому переименование включённого «Разрешить управление» продлевало допуск ещё на 30 минут, переименование вспомогательного переключателя отправляло команду с текущим значением, а работающие ускорение и сброс фильтра отвечали на переименование отказом. Проверено host-тестом; поведение приложения «Дом» при переименовании — NOT RUN.

Когда бризер выключен, `Fan.RotationSpeed` показывает 0%; сохранённая в Tion ступень остаётся во внутреннем reported state и используется при следующем включении через `Active`. Положительная скорость из HomeKit при выключенном бризере включает его и устанавливает выбранную ступень одной командой.

Начиная с `rc3-dev` температуры публикуются в диапазоне −50…100 °C: HomeSpan позволяет расширить HAP-диапазон через `setRange`, так делает его пример уличного датчика. Значение вне диапазона помечает `TemperatureSensor` неактивным/неисправным, а `HeaterCooler` сохраняет последнее допустимое показание; реальная величина доступна в диагностике. Отображение отрицательных значений в Apple «Дом» — NOT RUN. `HeaterCooler.CurrentTemperature` использует температуру выхода бризера, не комнаты. Кандидат не заявляет охлаждение или Auto. `AirPurifier` представляет фильтрацию притока в ручном режиме: его плитка выключила и снова включила бризер, предупреждение фильтра видно в «Доме». Настоящий сброс ресурса не выполнялся.

## Семантика команд и оставшиеся проверки

- Кадры рециркуляции, звука, подсветки, нагрева и уставки отправлялись на первый Tion и изменили ожидаемые поля. Для звука/подсветки используется сохраняющий `STATE_SAV`, для остальных — `STATE_SET`. Сброс фильтра допускается только после замены фильтра, при выключенном бризере и запрещённом нагреве; настоящая команда сброса не отправлялась.
- Изменение только уставки сохраняет питание и разрешение нагрева. Включение нагрева требует работающий бризер, приток, распознанный вариант ТЭНа и уставку 1–25 °C; рециркуляция блокирует его. На первом `02D0` при цели 24 °C raw heater_percent стал 4, но длительная терморегуляция и границы не проверены.
- После старта сначала поднять UART-обслуживание, выполнять только подтверждённый служебный обмен и запрос состояния, затем публиковать reported state.
- `ControlTransaction` сохраняет явный параметр разрешения legacy `02D0`; HomeKit-адаптер GM1 задаёт его постоянно по решению владельца. Основной набор команд испытан на первом `02D0`; на втором подтверждён ограниченный набор из таблицы. Ограничение upstream не оказалось запретом проверенных команд на первом контроллере, но не доказывает совместимость всех команд и ревизий.
- `update()` HomeSpan принимает либо отклоняет ограниченное намерение и не блокируется на UART. После ошибки карточка возвращается к reported value при следующем состоянии, диагностическая страница показывает причину и, если запись отклонил кодировщик, её повод (например, «breezer reports errors»), команда завершается отказом. Исход записи без подтверждения считается неуспехом. Допуск к записи решает только свежий pre-read: snapshot при постановке в очередь проверяет модель, прошивку, свежесть и контекст ускорения, но не саму запись. Если свежий pre-read уже содержит запрошенные значения, транзакция завершается исходом `Unchanged` без записи; это не ошибка.
- UART-адаптер выполняет одно намерение за раз и не повторяет запись автоматически. Пока оно выполняется, может ждать ещё одно. Команда, меняющая ту же группу полей одного кадра (питание и скорость; рециркуляция; звук и подсветка; нагрев и уставка), сливается с ожидающей: новые значения заменяют прежние, остальные поля сохраняются, поэтому при движении слайдера записываются первое и последнее значения, а питание и скорость из разных HAP-записей уходят одним кадром. Команда другой группы получает отказ HomeKit; сброс фильтра и контекстные команды ускорения никогда не ждут. Любой отказ отбрасывает ожидающую команду, а запрос, основанный на статусе до этого отказа, отклоняется по счётчику отказов. Каждая принятая команда получает тикет; статус хранит четыре последних исхода (`Applied`, `Unchanged`, `Failed`, `Merged`, `Dropped`), и ускорение и сброс фильтра следят за своим тикетом, а не за общими счётчиками. Тикет, выпавший из списка, считается неуспехом. Heartbeat имеет приоритет, штатные опросы состояния приостанавливаются, пока команда выполняется или ждёт. Просроченные намерения не исполняются после reconnect: срок 4 с считается с постановки в очередь, истечение до записи диагностируется отдельно от таймаута проверки.
- Сообщённые устройством ошибки блокируют любые записи, кроме выключения бризера и запрета нагрева: эти команды ведут к безопасному состоянию. Остальные проверки полного состояния для них сохраняются.
- В GM1 ускорение не зависит от срока допуска. Любая неудачная команда отменяет действующий таймер и его автоматический возврат; если скорость уже стала максимальной, её можно изменить новой командой HomeKit или штатным управлением.
- Черновик преобразования при максимуме `N`: ступень `s` из `[1,N]` → `100*s/N`; входной процент `p>0` → ближайшая ступень с ограничением `[1,N]` и фиксированным правилом midpoint. `0` — выключение. Проверить `step → percent → step` для каждого N и UI до утверждения.

## Восстановление после сбоев — кандидат

Предчтение и проверка команды ждут завершения прежних запросов состояния. Таймаут или ошибка TX не позволяют забыть ожидаемый ответ и принять его позже за новый. При потерянном ответе телеметрия продолжает обновляться, но команда может истечь без записи; автоматического повтора нет. Счётчик ожидаемых ответов доступен в диагностике. До получения всех ответов либо перезапуска стика новые записи не выполняются.

Программные перезапуски из-за паузы heartbeat и reset от watchdog/panic используют общий бюджет трёх попыток. После его исчерпания следующий старт оставляет UART и HomeKit выключенными и показывает красный светодиод. Отключение и подача питания разрешают новый запуск; минута исправной работы сбрасывает бюджет. Эти сценарии проверены на host с настоящим адаптером, аппаратно **NOT RUN**.

## Критерии для согласования до релиза

Предложение, не измерение: 99% принятых команд питания/скорости согласуются с устройством не позже 2 с в исправной сети; изменение пультом видно не позже 2 с; восстановление свежего состояния после краткой потери связи — до 30 с; 24 ч soak нового GM1 по решению владельца без пропуска обязательного обмена при сетевых сбоях и provisioning. Эти статистические критерии ещё **не измерены**; одиночные успешные действия их не заменяют.
