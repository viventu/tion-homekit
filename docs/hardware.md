# Аппаратный preflight — Draft

На двух снятых стиках 2026-09-23/24 проверены USB enumeration, ROM-связь и Flash 16 МБ. С каждого считан полный 16 МБ образ в локальный закрытый каталог `.private/backups/`; SHA-256 проверены. Заводская таблица разделов использует первые 4 МБ и совпадает с `huge_app.csv` закреплённого Arduino core. Разделы NVS двух стиков отличаются, поэтому образы строго привязаны к их MAC. На стик A записан транспортный read-only образ и затем диагностические HomeKit APP-образы. Повторный BOOT recovery проверен; перед обновлениями сохранена приватная NVS с настройками HomeKit, после каждой записи APP подтверждено её побайтное совпадение. `0.1.1-diag` запустился в штатном порту Tion и только читал состояние. `0.2.0-rc1-diag` прошёл первый прогон HomeKit-команд на первом Tion `02D0`; затем A обновлён до `0.2.0-rc2-diag` с сохранением NVS и сопряжения. Стик B с тем же `rc2` установлен во второй Tion `02D0`: подтверждены отдельное сопряжение, UART, питание, рециркуляция, звук, подсветка и пятиминутное ускорение с автоматическим возвратом. Подробности — в `docs/validation.md`.

## Снятый с бризера стик: первая прошивка и восстановление

1. Для каждого стика подтвердить именно базовую **T-Dongle-S3**, маркировку/ревизию, снять фото обеих сторон. Сверить реальные Flash/PSRAM с документацией LilyGO (16 МБ, без PSRAM). Не использовать параметры Plus/Dual.
2. Перед подключением к компьютеру снять стик с бризера. Обеспечить один источник питания. Не подключать обычный компьютерный USB-кабель к интеграционному порту Tion: форма разъёма не доказывает режим USB-host.
3. По инструкции LilyGO войти в ROM download, удерживая BOOT при подключении USB; идентифицировать чип и Flash только читающими командами. Не менять eFuse, Secure Boot или Flash Encryption. До новой прошивки сохранить проверяемый путь восстановления.
4. Сверить MAC порта с отдельной резервной копией именно этого стика и проверить её SHA-256. Для первого неизвестного устройства сначала использовать явно выбранный read-only образ; проверенный HomeKit-кандидат обновлять по отдельному preflight с закреплённой таблицей разделов; compile-only spike прошивать нельзя. Проверить повторный вход BOOT на снятом стике после прошивки.

Ожидается стабильное обнаружение ROM и читаемая идентификация. При несовпадении модели, ненормальном токе, нагреве или необходимости второго питания — остановиться. Восстановление: отключить, осмотреть, вновь войти в ROM download и вернуть только исходный образ того же стика. Полное восстановление перезаписывает NVS и тем самым возвращает сохранённые в нём исходные настройки.

## Работа в бризере: аппаратные условия

До вставки сравнить распиновку конкретной платы и порта Tion, питание, логические уровни, ориентацию и запас по току по схеме LilyGO, документации Tion и неинвазивным измерениям. GPIO20 TX/GPIO19 RX взяты из ESPHome upstream. Оба стика уже установлены владельцем без инструментального измерения питания; на каждом получен двусторонний UART-обмен и штатная работа бризера. Напряжение и запас по току остаются неизвестными для обоих устройств. Измерять подходящим высокоомным/изолированным прибором при единственном источнике питания. Не подключать PC или обычный USB-UART к работающему интеграционному порту без утверждённой схемы.

Первый допущенный опыт должен отправлять только известный heartbeat и запросы состояния/информации, без записей. Наблюдать питание с момента старта и при потере Wi-Fi, provisioning, reboot. Собирать временные метки постановки TX, окончания TX и валидного RX; вычислять максимальную **фактическую** паузу, не интервал запуска задачи. При потере питания, повторных reset, неожиданном изменении режима или включении ТЭНа — остановиться. Для восстановления снять стик и вернуть штатную работу бризера; не перезагружать его в цикле.

Порог 8–10 с — предупреждение upstream, не измерение на наших устройствах. Предварительный проектный ориентир: запрашивать heartbeat каждые 3 с и удерживать наблюдаемую паузу ниже 5 с под худшей известной нагрузкой. Превышение блокирует следующий срез; после прямого измерения ориентир пересмотреть. OTA при установке в Tion отключена.

## Диагностика без USB-консоли

В порту GPIO19/20 заняты UART и USB serial может быть недоступна. HomeKit-образ использует APA102 как статусный LED HomeSpan и `StatusFault` при устаревшем состоянии; отображение последнего в Apple «Дом» не проверено. Диагностическая сборка `TION_DIAGNOSTICS=1 scripts/build-homekit.sh` добавляет страницу `/tion-status` с числом ответов, возрастом состояния, максимальной паузой между завершениями heartbeat TX, ошибками UART и reset reason. Это обычная страница HomeSpan WebLog без HAP-аутентификации; применять её только в доверенной локальной сети, не публиковать наружу. Страница не содержит Wi-Fi-паролей и кодов сопряжения. Обычная сборка страницу не включает.

## Последовательность проверки

| Шаг | Ожидаемое свидетельство | Остановка/восстановление |
| --- | --- | --- |
| Снятый стик и ROM recovery | Идентификатор чипа, Flash, BOOT enumeration | При несовпадении отключить питание |
| Один Tion, только чтение | Firmware version, валидное состояние, питание при сетевом сбое | При reset/power loss снять стик |
| Питание и скорость вентилятора | Ответы, синхронизация с пультом | При самопроизвольном режиме вернуть read-only образ |
| Нагрев отдельным срезом | Раздельные permission/actual heat, безопасные лимиты | При аномалии температуры/ошибке перейти на штатное управление |
| Сеть, power cycle и второй стик | Нет старых команд; независимое сопряжение | При совпадении identity снять затронутый стик |
| Кандидат GM1 soak 24 ч (решение владельца 2026-09-26) | Логи пауз, памяти, восстановления и ошибок | При пропуске дедлайна отложить релиз |
