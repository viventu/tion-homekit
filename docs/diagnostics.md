# Диагностика

Обычная прошивка не открывает HTTP-страницу состояния. Для диагностики соберите вариант с суффиксом `-diag` в [настроенном окружении](../README.md#установка):

```sh
TION_DIAGNOSTICS=1 scripts/build-homekit.sh
```

Результат находится в `.build/homekit-diagnostics/`. Устанавливайте его по [инструкции обновления](setup.md#обновление-приложения-без-потери-сопряжения).

## Локальная страница

Откройте `http://tion-4s-XXXXXX.local/tion-status`, заменив `XXXXXX` суффиксом своего стика. Если имя не разрешается, используйте его адрес в домашней сети. Страница работает без аутентификации HomeKit и содержит идентификаторы устройства: не открывайте её порт в интернет и не публикуйте полный HTML или скриншот.

| Показатель | Что проверять |
| --- | --- |
| Firmware version | Соответствует установленной сборке |
| UART task / State fresh | Задача работает, состояние обновляется |
| Heartbeat TX age / Maximum heartbeat TX gap | Текущая и максимальная паузы передачи; критерий длительного теста — менее 5 с |
| Pending state replies | Не остаются необработанные ответы, блокирующие запись |
| TX failures / Rejected frames / Raw errors | Ошибки передачи, разбора кадров и контроллера |
| Free heap / Minimum free heap / UART stack free | Запас памяти и стека в динамике |
| Control available / исходы команд | Доступность управления и результат конкретных действий |

Отказ команды не всегда означает потерю сети. Например, нагрев в рециркуляции отклоняется намеренно. При потерянном ответе состояния телеметрия может обновляться, а запись оставаться заблокированной; причина описана в [архитектуре](architecture.md#запоздалые-ответы).

## Длительное наблюдение

Монитор читает HTTP-диагностику и не посылает управляющие команды. Компьютер должен оставаться включённым и доступным в той же сети. Для каждого устройства и версии создавайте отдельный новый файл; существующий CSV скрипт не перезаписывает.

Пример на 24 часа с минутным интервалом:

```sh
python3 scripts/monitor-diagnostics.py \
  --url http://tion-4s-XXXXXX.local/tion-status \
  --output .private/soak/observation.csv \
  --hours 24 --interval 60
```

На macOS можно поставить `caffeinate -i` перед `python3`, чтобы предотвратить автоматический сон при бездействии. Не закрывайте терминал с монитором. CSV создаётся с правами `0600`; он содержит выбранные метрики, но остаётся частным журналом эксплуатации.

Для проверки укажите ту же длительность, интервал и ожидаемую версию:

```sh
python3 scripts/review-soak.py .private/soak/observation.csv \
  --expected-hours 24 --interval 60 --expected-version 0.2.0-gm1-diag
```

Код завершения `0` означает прохождение автоматических порогов, `1` — обнаруженную проблему, `2` — недостаточную длительность. Проверяются версия, полнота журнала, доступность, перезапуски, свежесть UART, heartbeat, ошибки и запас памяти. Результат требует разбора контекста: например, намеренное отключение устройства попадёт в журнал как сбой. Минутные измерения не заменяют непрерывную трассу или электрический замер.

## Типовые ситуации

- **«Не отвечает» в Apple «Дом».** Проверьте питание, домашнюю сеть и свежесть UART. Если страница доступна, сравните состояние HomeKit и причины отказов команд. Не сбрасывайте сопряжение до выяснения причины.
- **После прошивки не появился Setup AP.** Полностью отключите USB и подключите без BOOT. AP автоматически нужен при отсутствии сохранённых Wi-Fi-настроек; с настроенным Wi-Fi ищите стик в домашней сети.
- **После ошибок горит красный светодиод.** Это может быть отказ запуска или исчерпание бюджета восстановления. Прекратите команды и проверьте [порядок восстановления](setup.md); не устраивайте циклические перезапуски.
- **После ускорения осталась максимальная скорость.** Ошибка или потеря свежего состояния отменяет автоматический возврат. Задайте нужную скорость штатным управлением либо в «Доме» после восстановления связи.

Для обращения в проект используйте [правила поддержки](../SUPPORT.md), передавая только необходимые обезличенные метрики.
