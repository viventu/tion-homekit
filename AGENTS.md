# Правила проекта Tion HomeKit

- Общаться с владельцем и писать проектные документы по-русски. Идентификаторы и комментарии в коде — по-английски.
- Двигаться небольшими проверяемыми срезами. Архитектура и контракт остаются Draft до подтверждения на устройстве.
- Аппаратные действия выполнять только после соответствующего preflight и с проверяемым восстановлением; не проводить fuzzing на реальном бризере, не менять eFuse или контроллер Tion.
- Не сохранять в репозитории Wi-Fi-пароли, коды и ключи сопряжения, дампы NVS, приватные конфиги. Не выполнять push, публикацию или выпуск бинарников без явного решения сопровождающего. Собственный код доступен по 0BSD; сторонние notices сохранять.
- Один стик обслуживает один бризер. Идентичности и pairing credentials независимы. В рабочем пути не использовать Homebridge, MQTT, BLE, облако и ESPHome runtime.
- Существенные утверждения проверять по версионированному upstream и фиксировать источник, статус и ограничения в `docs/evidence.md`. До копирования upstream-кода сохранить notices и проверить лицензии.
- Host-проверка: `scripts/test-host.sh`; на Linux с GCC — `scripts/test-host.sh --coverage` (100 % строк и ветвей). Compile-only spike: `scripts/check.sh` с версиями из README. Скрипты ничего не прошивают.
- Перед публичным снимком выполнить `scripts/prepare-public-snapshot.py` на чистом checkout; в GitHub отправлять только снимок без частной истории.
- Каждый срез отдельно проверять и критически пересматривать; аппаратные результаты обозначать NOT RUN до измерения.
